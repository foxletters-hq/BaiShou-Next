# AI 工具提示词

> **用途**：贡献者把下面整段粘贴到自己所用 AI 编码工具的「用户规则 / 自定义指令 / 系统提示词」里。这份提示词不依赖任何特定工具。它只负责把 AI 指到本仓库的规则目录；具体约定写在 `docs/1-AI-Code/` 里的规则文件中，改规则只改那些文件，不要为某个 IDE 再抄一份。

## 提示词正文（整段复制）

```text
1. 永远使用中文回复用户。

2. 项目的代码、注释、文档和提交信息里，不允许出现外部项目的名称。

3. 提交代码时，commit message 用中文写。单次改动超过 10 个文件时，先重新审查这些文件，再拆成多批提交，不要一次性提交。

4. 本项目的 AI 规则都在 docs/1-AI-Code/。动手前先打开 docs/1-AI-Code/0-README.md，它是这个目录的索引。根据当前工作在表里找到对应文件，只打开那一份，不要通读整个目录。表里对不上时，先列出 docs/1-AI-Code/ 下的文件，按文件名判断该打开哪一份。不要把规则再抄到某个编辑器或 AI 工具的专用配置里；改约定只改 docs/1-AI-Code/ 和 packages/ui/COMPONENTS.md。

5. 写界面之前先读 packages/ui/COMPONENTS.md，确认要用的组件是否已经存在。开关、勾选框、分段控件、按钮、输入框、下拉框只允许从 @baishou/ui（桌面端）或 @baishou/ui/native（移动端）引入，不允许在页面里用 CSS 或从 react-native 自己再实现一份。

6. 新增、重命名或删除 packages/ui 的公开组件时，把它登记到 scripts/ui-component-index.manifest.json 的对应分组，再执行 pnpm sync 重新生成 packages/ui/COMPONENTS.md 的清单。不要手工编辑清单区块。

7. 颜色、圆角、间距、阴影只能取 packages/ui/src/theme/css-variables.css 里的变量，不要在页面里写死数值。

8. 用完整、规范的中文说明你做了什么。可以使用技术名词，但要写清具体动作（新增、删除、保留、覆盖、合并、比较），不要用比喻或省略动词的说法代替动作。
```

## 为什么需要第 4 条

项目里的规则分散在几份文档中：编码与测试规范、UI 主题与布局规范、提交与 PR 规范、组件清单。全部塞进提示词会太长，也会随文档更新而过期。所以提示词只负责把 AI 指向 [0-README.md](./0-README.md) 所在的规则目录，由那一份维护「当前工作 → 打开哪一份规则」的对应表。以后改规则只改 `docs/1-AI-Code/` 里的文件（组件清单改 `packages/ui/COMPONENTS.md`），贡献者不用重新配置提示词，也不用给某个 IDE 单独适配一份。

规则入口特意放在 `docs/` 下，而不是放在某个 AI 工具专用的目录或文件里。本仓库的 `.gitignore` 把 AI 工具专用的目录和文件都排除在版本库之外，规则写在那里协作者克隆后拿不到。
