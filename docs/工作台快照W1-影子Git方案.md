# 工作台快照 W1：影子 Git 仓库

> 版本：v1.0
> 日期：2026-08-12
> 一句话：工作台的轮次快照从「JSON 里存文件全文」换成「应用数据目录里的影子 Git 仓库存 tree」，用户文件夹零侵入、二进制安全、体积可控。

## 零、先定边界：工作台是桌面独占能力

**移动端不做工作台，也不做工作台的快照与回滚。** 这不是排期问题，是三条硬约束叠在一起：

| 约束           | 具体表现                                                                         |
| -------------- | -------------------------------------------------------------------------------- |
| 跑不了原生 git | React Native 没有进程模型，dugite 是随桌面安装包分发的可执行文件，塞不进 APK/IPA |
| 拿不到文件夹   | Android SAF 与 iOS 沙盒给的是「一次一个文件」的授权，拿不到可长期读写的目录句柄  |
| 场景不成立     | 工作台的核心动作是审阅一屏 diff 再决定接受还是撤回，五寸屏上这件事本身没法做     |

这条决定一确立，快照层就不必为跨端付抽象税：

- 快照实现（`git-shadow-snapshot.store.ts`、`git-shadow-fs.ts`、`git-shadow-gc.ts`）直接用 `node:fs` / `node:path`，不做任何平台分支。
- 这些模块虽然在 `packages/ai/src/index.shared.ts` 的桶文件里，但移动端的 Metro 会把所有 `node:*` 解析到空 mock，且移动端没有任何调用点，因此不会进真实运行路径。
- **不要**为了「将来移动端也许要用」再加一层适配器。真要做的时候，缺的是文件夹授权与进程模型，不是抽象层。

## 一、为什么必须换掉全文 JSON

旧方案把文件全文塞进 `userData/agent-workspace-sessions.json`，并且靠写工具逐个上报路径才能捕获。三个后果：

**（1）二进制静默损坏。** `readFile(path, 'utf-8')` 读进来的图片、docx 已经不是原字节，回滚写回去就是一个坏文件。这挡住了 markdown 附带配图这类最普通的场景。

**（2）体积无上限。** 同一文件改 N 轮就存 N 份全文，没有淘汰机制，存档只增不减。

**（3）终端命令永久漏网。** `workspace_run` 不经过写工具，它造成的改动从来没进过快照，回滚撤不掉。

换成影子 Git 后三条同时消失，还顺手删掉了一批为「全文 JSON」打的补丁——旧实现里轮次开始只能建一个空壳 checkpoint（`paths: []`），内容靠工具边写边补进内存，于是「热内存比落盘更全」，于是需要一整套择优/合并逻辑。现在轮次开始一次 `write-tree` 就拿到完整的树，落盘只存 40 字符 SHA，不存在半全半空的中间态。

## 二、影子仓库：用户文件夹一个字节都不多

不在用户文件夹 `git init`，而是把仓库和工作树拆开：

```
GIT_DIR      = userData/workspace-shadow-git/<可读名>-<hash(folderRoot)>/
GIT_WORK_TREE = 用户选的工作台文件夹
```

用户目录里不会出现 `.git`，不会产生任何提交，用户自己的仓库完全不受影响。目录名用哈希是因为工作台路径可能很长、带中文或盘符，直接映射成目录名会在 Windows 上踩长路径与非法字符；前缀保留一段可读名字只是为了人工排查方便。

零新增依赖：dugite 已随安装包分发，`runBundledGit` 复用它并支持注入 `GIT_DIR` / `GIT_WORK_TREE`。

建仓时如果用户文件夹本身就是个 git 仓库，会把它的 `objects` 目录写进影子仓的 `alternates`，并复制一份索引——已有的哈希与 stat 缓存能直接复用，首次 capture 快很多，相同内容的 blob 也不会存两份。

**代价要写清楚：** 借来的对象归用户的仓库管。如果用户之后在自己仓库里跑 `git gc --prune`，把某个我们借用中的对象回收了，对应快照的恢复会直接报错。好在这类对象通常是已提交内容（在用户仓库里是可达的），真正落进这个窗口的情况很少；而且失败是显式报错，不会静默恢复出错误内容。

### 2.1 拍快照：只更新索引，不提交

```bash
git ... diff-files --name-only -z                      # 已跟踪文件里改过的
git ... ls-files --others --exclude-standard -z        # 未跟踪的新文件
# 过滤：忽略规则 + 单文件大小上限（只对 untracked 做 stat）
git ... rm  --cached -f --ignore-unmatch --pathspec-from-file=- --pathspec-file-nul
git ... add --all --sparse --pathspec-from-file=- --pathspec-file-nul
git ... write-tree                                     # → treeOid
git ... update-ref refs/snapshots/<treeOid> <treeOid>  # 给树挂引用，见 5.2
```

### 2.2 恢复：路径不在目标树里，就等于「删掉」

```bash
git ... ls-tree -r -z --name-only <tree> -- <files>   # 判断是否存在
git ... checkout <tree> -- <files>                    # 存在 → 恢复
# 不存在 → 文件系统直接删除
```

「不在树里」有两种截然不同的含义，混淆会丢数据：一种是这一轮才新建的文件，回滚就该删；另一种是被忽略规则或体积上限挡在快照之外的文件，它的旧内容我们从来没存过，删掉就是永久丢失。后者在恢复时会被识别出来并跳过——宁可留下一个本轮新建的大文件，也不能误删用户原有的文件。

### 2.3 建仓配置里两条是硬要求

```
core.autocrlf=false    core.longpaths=true    core.symlinks=true
core.quotepath=false   core.fsmonitor=false   core.untrackedCache=true
feature.manyFiles=true index.version=4        index.threads=true
gc.auto=0
```

`core.autocrlf=false` 与 `core.longpaths=true` 在 Windows 上不能省：前者防止回滚顺手改写换行符，后者避免深层路径直接失败。`gc.auto=0` 让每次 capture 的耗时可预测，对象回收改由显式治理触发（见第五节）。

并发按 `gitDirectory` 加互斥锁，同一影子仓串行，避免 `index.lock` 冲突；这把锁由快照 store 与 gc 共用。**capture 失败只记警告，永不阻塞对话。**

## 三、回滚范围：全集与归因子集

轮次开始拍 `startTree`，轮次结束拍 `endTree`：

- `diff(startTree, endTree)` = 这期间变化的**全集**，终端命令造的改动也在里面（漏网问题就此解决）
- 写工具上报的路径 = **归因子集**，精确知道哪些是 AI 干的

工具上报的语义因此变了：`ensurePathCaptured` 不再用于存内容，改名为「记录 AI 明确碰过哪些路径」，用途是防止回滚吞掉用户在外部编辑器的手改。

回滚与编辑重发的确认框会列出将要改动的文件清单；当全集大于归因子集时额外提示「另有 N 个文件在此期间变化，可能来自你自己的编辑」，由用户选择只撤 AI 的改动还是全部还原。

## 四、降级路径

git 不可用时（二进制缺失、网络盘、init 失败、目录过大）自动退回纯文本快照实现，并按工作台记住这次降级，不再反复重试。降级后能力受限——二进制不安全、终端改动漏网——这正是旧实现的水平，属于可接受的兜底。

体量护栏：单文件大小上限（超限的 untracked 文件不进快照）、单次快照文件数上限（默认 2 万，挡住「把整个用户主目录绑成工作台」）、单条 git 命令超时（15 秒）。

## 五、仓库治理

### 5.1 什么时候删

影子仓库按**文件夹**共享，一个文件夹可能绑着多个会话。所以删除会话或从列表移除工作台之后，都要回头问一句「还有别的会话在用这个文件夹吗」：

- 没有了 → 删掉整个影子仓库
- 还有 → 只做一次按需回收

会话删除还要同时清掉进程内的检查点表，只删磁盘记录的话内存会一直占到重启。

### 5.2 gc 为什么需要引用

`write-tree` 产出的树没有任何引用指向它，在 git 眼里就是垃圾对象——**一次 `gc --prune=now` 就会把所有历史快照连同正文全部回收掉**。所以每拍一张快照都要顺手挂一个 `refs/snapshots/<treeOid>` 引用。

回收时以检查点存档为唯一真相：先按存档里还活着的 `startTreeOid` / `endTreeOid` 校准引用（补上缺的、删掉多的），再让 git 按可达性回收。任何一步对不上就跳过 gc——引用少挂一个，被回收的就是某个检查点的全部正文，那个会话从此回滚不了；占着磁盘远比丢数据便宜。

触发时机是按需的：影子仓库超过 512 MB 才回收，同一工作台 30 分钟内只量一次体积（递归量对象库本身有成本）。

## 六、明确不做

- 移动端工作台（含移动端快照与回滚），理由见第零节。
- 不在用户文件夹执行 `git init`，不产生任何提交到用户仓库。
- 不做「可反悔的三态回滚」（stage / clear / commit），但接口没堵死后续扩展。
- 不做 Word / Excel 的编辑能力本身；本方案只保证存储层对二进制安全，为将来留门。
- 不迁移历史 checkpoint，只保证旧格式还能继续回滚；新轮次一律走 git。

## 七、验收清单

自动化：

- 真 git 集成测试（`mkdtemp` 临时目录）覆盖增 / 改 / 删 / 重命名 / 二进制 / 中文路径 / 深路径 / CRLF，全部断言磁盘最终状态。
- gc 集成测试：跑完 `gc --prune=now` 之后，仍在检查点里的快照必须能正常回滚。
- 纯逻辑单测：排除规则、大小上限、路径布局、降级判定、回滚范围计算、gc 引用校准。

手动：

- 终端命令（`workspace_run`）创建的文件，回滚**应该**能撤掉。
- 用户在外部编辑器的手改，**不应**被静默吞掉——确认框要把它单列出来。
- 工作台文件夹里不应出现 `.git`；用户自己的仓库 `git status` 不应有任何变化。
