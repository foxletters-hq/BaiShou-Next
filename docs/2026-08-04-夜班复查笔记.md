## 二、今晚在想什么（思路主线）

### 2.1 从「仓库归属是什么」到「仓库竟然没有 ID」

起点不是重命名，而是 **V1 数据面隔离**：磁盘目录按仓分开了，但共用 `baishou_agent.db` 时检索 / 会话列表 / 删仓清库大多不过滤仓库。`group_id` 被当成杂物抽屉（`memory:Personal`、`diary_batch`、会话 id、`manual`…），不能当隔离键。

做隔离时发现更底层的问题：**`VaultInfo` 只有 name，没有稳定 ID**。名字同时是：

- 磁盘目录名
- 数据库「外键」
- 向量 `group_id` / `source_id` 前缀
- 增量同步路径的第一段

产品里一直没有重命名入口，所以没炸。但 V1.0 刚加的 `vault_name` 列**还没发布**，V1.4 又要再加两列——此刻不改成 ID，以后就是多表二次迁移。

**决策：插入 V2（身份）到 V1.4 之前；目录名跟着显示名走（所见即所得）；改名用服务端移动优化，失败回落朴素重传。**

### 2.2 几个反直觉但必须记住的判断

1. **ID 不能只写在 `vault_registry.json`**  
   注册表本身同步；老客户端会吞掉未知字段；两台设备各自升级若随机发号会分叉。  
   → 三级来源：`vault.json` > 注册表 > `deriveLegacyVaultId(name)`（存量确定性派生）；新建用随机 ID。

2. **改名绝不能重写 Memory/Graph/Session 文件里的 `vaultName` 字段**  
   一改 hash 全变 → 全量重传，服务端移动优化白做。  
   → 新写入 dual-write `vaultId`+`vaultName`；读取优先 id / 路径；旧文件不动。

3. **改名方：迁本地 manifest，不动祖先快照**  
   祖先 =「上次与远端一致」；远端还是旧路径时若迁祖先，合并会判 `delete-local`。  
   → 跟随设备才两边都迁。

4. **`group_id` 可以扔仓库名，`source_id` 前缀必须留**  
   有了 `vault_id` 列后 `memory:`/`diary:` 拼名是冗余；但 `source_id` 的前缀管全局唯一（删向量按 source），改成 `vlt_…#diaryId`。

5. **遗留手动记忆：复制到各仓，不要 `vault_id='*'`**  
   旧实现全局可见；隔离后若只归一个仓是可感知退化。复制 + `derivedFromLegacyId` 幂等；新建仓不补。

6. **设置是全局的，方向和用户数据相反**  
   从仓内 `.baishou/settings` 搬到存储根；同步用 `global` scope。

7. **知识库 / 图谱往后推**  
   今晚目标是把仓库隔离与身份做透；K1、G1 方案保留，施工排队。
