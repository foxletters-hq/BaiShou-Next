## 一、为什么要改

### 1.1 第一屏该表达什么

工作台权限的第一屏只需要回答两件事：「这个项目我放手到什么范围」和「还要不要每步问我」。常见做法是：

| 形态         | 主界面控件                                                       | 底层                                                            |
| ------------ | ---------------------------------------------------------------- | --------------------------------------------------------------- |
| 安全预设     | 1 个预设下拉，选「自定义」才展开细项                             | 分层 allow/deny 规则表                                          |
| 两维正交     | 审批时机 × 活动范围（或沙盒）两个下拉                            | 两维独立组合                                                    |
| 临时通道     | 1 个「自动接受」开关                                             | 开关外另有完整规则引擎                                          |
| **白守现状** | **5 行能力矩阵 + 可信目录 + 命令前缀 + 隐藏工具开关 + 重复阈值** | profile + permissionRules + allowlist + exclusionList，四套并行 |

细粒度矩阵不该占第一屏。白守当前第一屏信息量过大，而实际使用中多数场景只需要表达「这个项目我放手」或「这个项目每步都问我」。

### 1.2 现状的两个硬伤

**硬伤 A：表达不了「宽泛规则 + 具体豁免」。**

求值用的是「最强效果赢」：

```92:99:packages/shared/src/baishou-agent-gate/agent-gate-ruleset.util.ts
export function combineAgentGateRuleEffects(
  effects: readonly AgentGateEffect[]
): AgentGateEffect | undefined {
  if (effects.length === 0) return undefined
  return effects.reduce((strongest, effect) =>
    EFFECT_PRECEDENCE[effect] > EFFECT_PRECEDENCE[strongest] ? effect : strongest
  )
}
```

Deny(3) > Ask(2) > Allow(1)。后果是「命令一律询问，但 `git status` 直接放行」这条规则写不出来——Ask 永远压过 Allow。目前靠 shell allowlist 走旁路绕开，但换成「编辑一律询问，但 `docs/**` 放行」就没有旁路可走了。

**硬伤 B：区外路径是求值链里的特殊分支，不是一条普通规则。**

`baishou-agent-gate-policy.service.ts` 的 `evaluate()` 里，区外路径独占一段 if 分支，牵扯 4 个专用配置字段（`forceAskExternalPath`、`externalPathEffect`、`trustedExternalDirs`，外加 `matchesTrustedExternalDirs` 这个专用匹配器）。每加一种资源类型就要再加一段分支。

### 1.3 目标模型（本方案采用）

**（1）全局唯一原语。** 所有工具都走同一套 `assert` / `ask`，没有第二条旁路。

**（2）`always` 的粒度由工具自己声明。**

```ts
// edit / read / glob：整项放行
ctx.ask({ permission: 'edit', patterns: [relPath], always: ['*'] })
// shell：只记住扫描出的命令前缀
ctx.ask({ permission: 'bash', patterns: [...scan.patterns], always: [...scan.always] })
// external_directory：只记住那一个目录 glob
ctx.ask({ permission: 'external_directory', patterns: globs, always: globs })
```

**（3）求值是「最后匹配赢」，不是「最强效果赢」。**

```ts
rulesets
  .flat()
  .findLast(
    (rule) => Wildcard.match(permission, rule.permission) && Wildcard.match(pattern, rule.pattern)
  ) ?? { action: 'ask', permission, pattern: '*' }
```

配置书写顺序就是优先级。例如 `{"*": "deny", bash: "allow"}` → bash 允许；`{bash: "allow", "*": "deny"}` → bash 拒绝。

**（4）分层就是数组拼接。** 场景默认 → 预设 → 工作区 → 记忆 → 会话，求值时按顺序拼接，运行时批准追加在最后。没有「继承 / 覆盖」的特殊语义，只有顺序。

**（5）区外目录是一个普通 permission key。** `external_directory` 和读写能力平级，可信目录就是一条普通 allow 规则。触及区外时工具**额外**发一次 ask，两道门天然串联。

**（6）临时放行和持久策略彻底分家。** 「本工作区自动接受」是独立开关，**完全不进规则集**。

## 二、目标与非目标

### 目标

1. 工作台权限主界面收敛到 2 个下拉 + 1 个开关，细粒度进「自定义」折叠区。
2. 求值语义换成「分层 + 最后匹配赢」，让具体规则可以豁免宽泛规则。
3. 区外路径从特殊分支降级为普通权限键，删掉 3 个专用配置字段。
4. 新增「本工作区自动接受」临时通道，不写入持久策略。
5. `always` 记忆粒度由工具声明，中心侧只做安全校验。

### 非目标

- 不改 Gate 的对外接口（`assert` / `ask` / `reply` 三个方法签名保持）。
- 不动伙伴（companion）场景的 UI，本期只改工作台。
- 不引入 OS 级沙盒，白守的隔离仍在应用层。
- 不做规则的可视化编辑器，高级规则继续用现在的表单。
- 文档只描述白守自身模型，不引用外部产品或仓库名。

## 三、核心决策

### D1：求值改为「分层 + 最后匹配赢」，红线用钳制层兜底

新的求值链：

```
1. toolDisabled                          → Deny（不变）
2. 拼接分层规则集，findLast 命中者胜
     [0] 场景默认层  AGENT_GATE_PROFILE_DEFAULT_RULES[profileId]
     [1] 预设层      当前预设展开出的规则
     [2] 工作区层    用户在该工作区的自定义规则
     [3] 记忆层      「始终允许」写入的规则（原 allowlist）
     [4] 会话层      自动接受 / 本次运行时批准
   未命中 → Ask
3. 钳制：命中 exclusionList / forceExclusion / destructive 风险档
     且结果为 Allow → 降级为 Ask
4. 钳制：预览被截断或命中危险命令 且结果为 Allow → 降级为 Ask（现有逻辑保留）
```

**为什么钳制比「最先返回 Ask」更好。** 现状是 exclusion 命中就直接 `return Ask`，意味着用户明确写了 `workspace_delete: deny` 也只会得到 Ask——Deny 被吞掉了。改成钳制后，Deny 能正常生效，Allow 被压回 Ask，安全性不降反升。

**为什么改成最后匹配赢不会降低安全性。** 唯一的风险是用户写了 `*: allow` 把一切放开，但第 3 步的钳制层保证删除类、`workspace_run`、`external_directory` 这些仍会问。也就是：**宽泛的 allow 只能放开「安全档」的东西，放不开红线。**

### D2：主界面两维正交，矩阵降级为「自定义」

第一屏只有三个控件：

| 控件                 | 取值                                       | 语义              |
| -------------------- | ------------------------------------------ | ----------------- |
| **活动范围**         | 只读 / 工作区内可写 / 含可信目录           | AI 能碰到多大范围 |
| **审批时机**         | 每步都问 / 仅危险操作问 / 不问（自动接受） | 什么时候打断你    |
| **自动接受**（开关） | 开 / 关                                    | 见 D3，临时通道   |

两个下拉各自展开成一组规则，落进 §D1 的 `[1] 预设层`：

| 活动范围     | 展开的规则                                                                                                                                                          |
| ------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 只读         | `workspace_list: allow`、`workspace_read: allow`、`workspace_write/patch/rename: deny`、`workspace_delete: deny`、`workspace_run: deny`、`external_directory: deny` |
| 工作区内可写 | 上面基础上 `workspace_write/patch/rename` 交给「审批时机」决定，`external_directory: deny`                                                                          |
| 含可信目录   | 再加上每个已登记目录一条 `external_directory: { "<dir>/**": allow }`                                                                                                |

| 审批时机     | 展开的规则                                                                    |
| ------------ | ----------------------------------------------------------------------------- |
| 每步都问     | `*: ask` 垫底                                                                 |
| 仅危险操作问 | `*: allow` 垫底，`workspace_delete / workspace_run / external_directory: ask` |
| 不问         | `*: allow` 垫底（红线仍被 D1 第 3 步钳制）                                    |

用户手动改任何一条细项 → 两个下拉都显示「自定义」，规则原样保留。从「自定义」切回预设时弹一次确认，提示会覆盖手改的托管规则。

**这一步删掉的东西**：`WORKSPACE_GATE_CAPABILITIES` 五行矩阵从第一屏移到自定义折叠区（组件本身不删）；`trustMode`（Manual / FullTrust）彻底删除——它已经被矩阵取代，只剩 `effectForActions` 里的 legacy 分支在读它，是个双写来源。

### D3：自动接受按工作区，落盘但常驻可见

存储与策略分离，不进 `BaishouAgentGateConfig`：

```ts
/** userData/agent-workspace-auto-accept.json，与权限策略分开存 */
interface WorkspaceAutoAcceptStore {
  version: 1
  /** key = workspaceId；不存在视为 false */
  byWorkspaceId: Record<string, boolean>
}
```

**行为约定：**

- 求值时作为 `[4] 会话层` 注入一条 `{ permission: '*', pattern: '*', action: 'allow' }`。
- 红线钳制（D1 第 3 步）照常生效——自动接受不等于「删文件也不问」。
- 工作台顶栏常驻一个醒目指示器 + 一键关闭，开着的时候必须一眼可见。
- 切换工作区时不继承，各工作区独立。

**为什么落盘而不是仅内存。** 用户选择工作区级作用域，本身就意味着期望它跨会话保持。风险由「常驻指示器」而不是「自动失效」来控制。

### D4：区外路径降级为普通权限键

新增权限键 `external_directory`，与 `workspace_read` / `workspace_write` 平级。触及区外时，工具**先**发一次区外门 assert，通过后**再**发本来的能力 assert：

```
workspace_read('D:/Notes/a.md')
  → assert('external_directory', patterns: ['D:/Notes/**'])   // 第一道门
  → assert('workspace_read',     patterns: ['D:/Notes/a.md']) // 第二道门
```

**删掉的字段**：`forceAskExternalPath`、`externalPathEffect`、`trustedExternalDirs`，以及 `matchesTrustedExternalDirs`、`shouldForceAskExternal` 两个函数和 `evaluate()` 里那整段 if 分支。

**可信目录的新表达**：就是一条普通规则 `{ permission: 'external_directory', pattern: 'D:/Notes/**', action: 'allow' }`。设置页那个「可信区外目录」列表变成这条规则的一个便捷编辑器，不再是独立的配置字段。

**语义等价性检查**：现状「区外默认 Ask + 可信目录放行 + 可信目录内仍走能力矩阵」在新模型下自动成立——因为两道门是串联的，第一道门放行不代表第二道门放行。

### D5：`always` 粒度下放给工具声明

`AgentGateToolMetadata` 增加一个可选字段：

```ts
export interface AgentGateToolMetadata {
  // ...现有字段
  /** 用户点「始终允许」时要记住的 pattern；缺省为 ['*']（整项放行） */
  buildAlwaysPatterns?: (args: unknown, ctx: unknown) => string[]
}
```

各工具的声明：

| action                                                     | alwaysPatterns              |
| ---------------------------------------------------------- | --------------------------- |
| `workspace_list` / `workspace_read`                        | `['*']`                     |
| `workspace_write` / `workspace_patch` / `workspace_rename` | `['*']`（后续可改为按目录） |
| `workspace_run`                                            | 结构化解析出的安全命令前缀  |
| `external_directory`                                       | 该目录的 glob               |
| `workspace_delete`                                         | `[]`（不允许 always）       |

中心侧的 `canPermanentlyAllowAgentGateAction` 从「猜每个 action 能不能永久放行」缩减为纯安全校验：拒绝空数组、拒绝裸 `*` 落到 `workspace_run`、拒绝命中 exclusionList。新增工具时不再需要回来改这个函数。

## 四、数据模型

### 4.1 新的配置结构

```ts
/** 规则：permission + pattern + effect，书写顺序即优先级（最后匹配赢） */
interface AgentGateRule {
  permission: string // 原 action，支持 workspace_* 通配
  pattern: string // 资源 glob；'*' 表示整项
  effect: AgentGateEffect
}

type AgentGateScopePreset = 'readonly' | 'workspace_write' | 'with_trusted_dirs' | 'custom'
type AgentGateApprovalPreset = 'always_ask' | 'dangerous_only' | 'never_ask' | 'custom'

interface WorkspaceGatePolicyV2 {
  version: 2
  /** 两维预设；任一为 custom 时忽略对应的展开规则，直接用 rules */
  scopePreset: AgentGateScopePreset
  approvalPreset: AgentGateApprovalPreset
  /** [1] 预设层 + [2] 工作区层合并后的有序规则表 */
  rules: AgentGateRule[]
  /** [3] 记忆层：来自会话「始终允许」，与 rules 分开存便于单独清空 */
  remembered: AgentGateRule[]
  /** 红线：永不允许 always 的 action */
  exclusionList: string[]
  hideDeniedTools: boolean
  repeatAssertAskThreshold: number
}
```

### 4.2 新旧字段对照

| 旧字段                     | 去向                                                                                     |
| -------------------------- | ---------------------------------------------------------------------------------------- |
| `trustMode`                | **删除**。FullTrust 等价于 `approvalPreset: 'never_ask'`                                 |
| `permissionRules`          | 改名 `rules`，数组顺序从「无意义」变成「优先级」                                         |
| `actionRules`              | **删除**（已是 legacy，`resolveAgentGatePermissionRules` 一并删）                        |
| `allowlist`                | 改名 `remembered`，条目结构从 `{action, pattern?, resourceKind?}` 收敛为 `AgentGateRule` |
| `forceAskExternalPath`     | **删除**，见 D4                                                                          |
| `externalPathEffect`       | **删除**，见 D4                                                                          |
| `trustedExternalDirs`      | **删除**，转成 `external_directory` 的 allow 规则                                        |
| `exclusionList`            | 保留，语义从「命中即 Ask」改为「命中则 Allow 降级为 Ask」                                |
| `hideDeniedTools`          | 保留                                                                                     |
| `repeatAssertAskThreshold` | 保留                                                                                     |

### 4.3 迁移函数

`agent-workspace-policy.store.ts` 读盘时按 `version` 分流，v1 → v2 的转换规则：

1. `trustMode === FullTrust` → `approvalPreset = 'never_ask'`，否则先设 `'custom'`。
2. `permissionRules` 按「无 pattern 在前、有 pattern 在后」稳定排序后写入 `rules`——保证具体规则在新语义下能赢过宽泛规则，这是旧「最强效果赢」到新「最后匹配赢」的等价性关键。
3. `trustedExternalDirs` 每项转 `{ permission: 'external_directory', pattern: '<dir>/**', effect: Allow }` 追加到 `rules` 末尾。
4. `externalPathEffect === 'deny'` → 追加 `{ permission: 'external_directory', pattern: '*', effect: Deny }` 到 `rules` **开头**（当垫底规则）。
5. `allowlist` 逐条转 `remembered`。
6. 反推 `scopePreset`：若转换结果恰好等于某个预设的展开，就标成那个预设，否则 `'custom'`。

迁移只在读盘时做一次并回写，v1 文件保留一份 `.bak`。

## 五、UI 结构

### 5.1 工作台权限页（第一屏）

```
工作台权限                                    [工作区: life-book ▾]

┌─ 活动范围 ─────────────────────────────────┐
│ AI 在这个工作区能碰到多大范围       [工作区内可写 ▾] │
├─ 审批时机 ─────────────────────────────────┤
│ 什么时候需要你确认                 [仅危险操作问 ▾] │
└────────────────────────────────────────────┘

可信区外目录                                    （仅当活动范围=含可信目录时出现）
  D:/Notes/**                              [移除]
  [+ 添加目录]

▸ 自定义规则（5 条）
▸ 已记住的允许（3 条）
▸ 高级
```

- 选「含可信目录」才出现目录列表，其余两档隐藏。
- 「自定义规则」折叠区里放现在的 5 行能力矩阵 + 有序规则表（可拖拽调序，因为顺序现在有意义了）。
- 「已记住的允许」= `remembered`，标注来源会话和时间，可单条删除 / 一键清空。
- 「高级」放 `hideDeniedTools`、`repeatAssertAskThreshold`、`exclusionList`。

### 5.2 工作台顶栏

自动接受开关放这里，不放设置页——它是操作态而非配置态。开启时顶栏显示常驻标识（建议用警示色 + 「自动接受中」文案 + 点击即关）。

### 5.3 权限卡片

新增一行来源说明，解决分层带来的「为什么问我 / 为什么没问我」不可见问题：

```
运行命令  git push origin main
来源：工作区规则「workspace_run → 询问」
[仅此一次] [始终允许 git push *] [拒绝]
```

「始终允许」按钮的文案直接展示 D5 声明的 `alwaysPatterns`，用户点之前就知道自己在授权什么。

## 八、风险与权衡

**风险 1：「最后匹配赢」把安全模型从「保守优先」改成「顺序优先」。**
缓解：D1 第 3 步的钳制层是硬编码的，不受规则顺序影响。另外要补一组专门的对抗测试——用 `*: allow` 打头，逐个验证删除、命令、区外三类仍然被拦。

**风险 2：分层后「有效权限」不可见。**
缓解：卡片上的来源说明（§5.3），以及自定义规则折叠区里按层分组展示（场景默认层只读、其余可编辑）。

**风险 3：预设与细项的双向绑定容易出状态机 bug。**
约定：细项改动只单向把预设推到 `custom`，绝不反向推断；只有用户显式选回某个预设时才重建托管规则，且必须弹确认。

**风险 4：自动接受落盘后用户忘了关。**
靠顶栏常驻指示器兜底。如果实测下来仍有误伤，退路是加一个「N 小时后自动关闭」，而不是改回内存态。

**未解决的权衡：是否要引入「全局工作台默认」层。**
本方案暂不引入——多一层就多一层不可见性，而白守的工作区数量通常是个位数，重复配置的成本还没高到需要继承。若后续工作区数量上去了，加在 `[1] 预设层` 之前即可，架构上是开放的。
