製品内の名称は **RAG 記憶管理** で、画面によっては「セマンティック検索庫」と書かれています。日記をチャンクに分けてベクトル化し、パートナーが意味の近さで具体的な断片を探せるようにする機能です。

初めて設定する場合は、先に [10 分で話し始める](/ja/docs/getting-started/quick-start/) でスイッチ、埋め込みモデル、日記の取り込みを確認してください。このページはパラメータ、移行、トラブルシュートです。

## 「思い出」とは別のものです

| | 思い出の年輪 | RAG |
|--|----------|-----|
| 形態 | 週記や月報のような要約ドキュメント | ベクトル塊と検索インデックス |
| 目的 | 人生のタイムラインを圧縮する | ある具体的な断片を正確に見つける |
| 誰が使うか | 共同の思い出の生成とコピー | パートナーがセマンティック検索ツールを呼び出す |

この 2 つは並行して動き、衝突しません。要約が全体像を担い、RAG が細部を担います。

## 日記はどうやって RAG に入るか

1. まずグローバル既定モデルで埋め込みモデルを設定します。
2. 以降は日記を保存すると自動で埋め込みが試行されます。
3. 漏れや失敗があれば、RAG ページで **未インデックス日記のフルスキャン** を押して補います。

手動で記憶の断片を追加し、セマンティック検索や全文検索で見返すこともできます。

画面にはベクトル塊の数、次元、キャッシュ使用量、現在のワークスペースの日記ベクトル数なども表示されます。

## 調整できるパラメータ

- 想起数 Top-K：1 回に何個の断片を取り出すか
- 類似度しきい値：このスコアを下回るものはヒット扱いにしません
- 想起の切り詰め Tokens：コンテキストに注入する長さの上限
- バッチ埋め込みの並列数

何も見つからないときは、たいていしきい値を上げすぎています。

## 埋め込みモデルを変えたら移行が必要です

埋め込みモデルが違うとベクトルの次元は基本的に互換しません。モデルを変えたら、必ずクライアントの案内に従って **埋め込みモデル移行** を実行してください。手順の中でバックアップ、続行、復元、キャンセルを選べます。

:::danger[移行をスキップしないでください]
古いベクトルを新しいモデルに無理に混ぜて使うと、検索結果が乱れるか、まったく使えなくなります。
:::

## パートナーが「覚えていない」ときの調べ方

この順で確認してください。

1. そのパートナーは親密パートナーですか。セマンティック検索や記憶系のツールは有効ですか。仕事パートナーは既定でこれらを使えません。
2. 埋め込みモデルは設定できていますか。接続テストは通りますか。
3. RAG ページに未インデックスや失敗の表示は出ていませんか。
4. 旧版から移行した直後ですか。日記は入っていても、ベクトル庫はもう一度フルスキャンし直す必要があります。
5. 類似度しきい値が高すぎませんか。少し下げるか Top-K を増やして試してください。

パートナー種別の違いは [AI パートナーと会話](/ja/docs/basics/companions/) を参照してください。
