「まるごと持ち出したい」「何かあったら戻したい」ときは、増分同期ではなくバックアップを使ってください。

## どんな種類があるか

| 機能 | 説明 |
|------|------|
| ローカル ZIP バックアップ | 完全なバックアップパッケージのエクスポートとインポート |
| クラウドバックアップ | フルパッケージを S3 または WebDAV に置く。パスは増分同期と分かれています |
| ローカルスナップショット | 重要な操作の前に自動で保護。トリガー条件はバージョンによります |
| LAN 転送 | 同一 Wi-Fi 内で端末間にライブラリ全体を転送 |

## エクスポートの習慣

定期的にローカル ZIP を作り、外付け HDD や別のクラウドなど 2 つ目の場所にコピーしてください。1 か所に置いただけではバックアップとは呼べません。

大きなバージョンアップや移行の前には、まずバックアップを取ってください。

インポート前には、対象端末の空き容量を確認し、上書きの警告を最後まで読んでください。

## インポート時の注意

インポートは既存データを上書きすることがあります。警告を読まずに確定を押し続けないでください。

旧版から来た場合は [バージョン移行](/ja/docs/migrate/from-legacy/) を優先してください。ディレクトリを適当に展開すれば済む、とは考えないでください。

インポート後にパートナーが急に「記憶喪失」になったら、RAG ページで [フルスキャン](/ja/docs/configure/rag/) を一度実行してください。たいていはベクトル庫が追いついていないだけです。

## 添付

**添付管理** では日記の添付とセッションの添付を確認でき、孤立したファイルを整理できます。整理前に、まだ参照されている内容がないか確認してください。
